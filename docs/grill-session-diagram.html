開発管理課タスク状況管理

グループセッション用 — グリルで整理した現状の図解

課長視点 Phase 1 進行中 モック（JSON） 明日の成功＝共感

1. 何のためのツールか（一言）

課のタスクをテーマ別に整理し、誰が・何を・いつまでを見える化する。
いちばん先に減らしたいのは担当が空のタスク（抜け）。

2. いま困っていること（痛み）

誰が 担当なし・未記載 → 最優先で見たい
何を 1タスク＝1行で追う
いつ 期限は推奨（空でも可）
全体 負荷・抜けの見える化（第2ラウンド）

3. 進め方（2フェーズ）

Phase 1 — いま

個人（課長）で型を固める

自分の課の整理に使う。デモと物語を整える。完成品の評価は求めない。

→
Phase 2 — いずれ

課チームで共有

同じ見方で「誰・何・いつ・抜け」を見る。共有の第一歩は未決（セッション後に詰める）。

4. 画面の型（4ペイン）

左から右へ、テーマ → 一覧 → 状況・次の一手 → 備考

PANE 1
テーマ選択
課の取り組みテーマ（下記）。メンバー名はここにしない。
PANE 2
タスク一覧
未着手/進行中/保留/完了。行に担当名＋未割当バッジ（目標）。
PANE 3
状況＋次の一手
公式の「次にやること」はここだけ。
PANE 4
備考のみ
時系列メモ。次の一手は書かない。
テーマを選ぶ → タスクを選ぶ → 状況・次の一手を確認 → 備考を追記

Pane 1 のテーマ例（課の重点テーマ）

人財育成 生産性向上 品質向上 パートナーマネジメント 新人研修 採用 その他

5. プロトタイプのいまと、グリル後の目標

項目 いま（デモ） 目標（グリル合意）
ワークスペース名 開発管理課タスク状況管理 済

6. 今日のセッションで話すこと

30秒ピッチ（そのまま話せる）

私は課長として、課のタスクをテーマ別（人財育成・生産性・品質など）に整理し、 それぞれについて誰が・何を・いつまでやっているかを一目で見たいです。 いちばん困っているのは担当が決まっていない／書かれていないタスクです。 まず自分の中で型を作り、のちにチームで同じ見方を共有したいと考えています。

お願い：完成度の採点より、「課長としてこう見たい、わかる／足りない」の共感を聞かせてください
