# dev-mgmt-task-board — プロダクト整理（グリルメモ）

グリル（要件深掘り）で合意した内容をまとめたドキュメントです。

**最終更新**: 2026-05-24  
**対象リポジトリ**: `dev-mgmt-task-board`

---

## 1. 一言で言うと

> 4月着任の課長として、課員が**今何をどのくらい抱えているか**を見える化し、  
> **年度目標と日々の作業がつながっているか**を把握する。  
> 作業を振る前に「手がいっぱい」と断られる事態を防ぎ、適切な作業配分を実現する。

---

## 2. 背景・課長の状況

- 4月に**新規着任**したばかりで課員の作業内容が見えず不安
- 課には**年度目標**（課の重点テーマ）が設定されている
- 課員は**日々の眼の前の業務**に集中しており、それが目標達成に結びついているかが不明
- 作業を振ろうとして「今 XX に向けて手がいっぱいです」と断られた経験あり
- 優先順位の正しさ・作業の必要性を把握したい

---

## 3. フェーズ

| フェーズ | 内容 | 状態 |
|----------|------|------|
| **Phase 1（いま）** | 課長個人が入力・整理し、型と運用を固める | **進行中** |
| **Phase 2（いずれ）** | 課員が入力・更新する運用に移行。人別フィルタも検討 | 未決 |

Phase 2 の共有方法（閲覧のみ / 週次で並べる / 集約ボード）は未決。

---

## 4. 解きたい課題

### 最優先
**状況の見える化** — 誰が今何を・どのくらい抱えているか

### 課題の3要素
- **誰が** — 課員の個人名でタスクに担当を付ける
- **何を** — 年度目標に紐づく実行タスク（1行＝1件）
- **いつ** — 期限は推奨（入力を促すが空でも可）

### 抜けの優先順位
1. **現在の負荷が見えない**（最優先）
2. 期限まわり（第2ラウンド）
3. 担当なし（第2ラウンド）
4. 負荷の偏り（第2ラウンド）

---

## 5. 課員ビューの仕様（合意済み）

- 課員ビューで課員を選択すると、**その人の担当タスクを全テーマ横断で Pane 2 に表示する**
- 「この人が今何を抱えているか」を一望するための全体把握ビュー
- テーマ絞り込みは行わない（Pane 1 のテーマ選択は目標ビューにのみ影響する）

---

## 6. 4ペインの役割（合意済み）

```
Pane 1            Pane 2                  Pane 3              Pane 4
年度目標選択  →  タスク一覧           →  状況・次の一手  →  備考のみ
               （ステータス別）           （課長が書く）      （時系列メモ）
               （担当名を行に常時表示）                       （将来: 音声受け皿）
```

| Pane | 役割 | 備考 |
|------|------|------|
| **Pane 1** | **年度目標**の選択 | 課の取り組みテーマ単位 |
| **Pane 2** | 選択目標内のタスク一覧 | ステータス別。**行に担当者名を常時表示** |
| **Pane 3** | **状況** ＋ **次の一手（公式）** | Phase 1 は課長が書く。空欄＝把握できていない箇所 |
| **Pane 4** | **備考のみ**（時系列メモ） | 次の一手は書かない。将来は音声文字起こし受け皿 |

### Pane 1 のカテゴリ（年度目標の例）

課の重点テーマ＝**年度目標**:

- 品質向上
- 生産性向上
- 人財育成
- パートナーマネジメント
- 新人研修
- 採用
- その他

※ 担当は**行（タスク）の個人名**。カテゴリは**年度目標**（メンバー名をカテゴリにしない）。

### ステータス（4値固定）

- 未着手 / 進行中 / 保留 / 完了

### 担当の見せ方

- **Pane2 の行に個人名を常時表示**（切り替えなし）
- 課員1人あたり数件〜10件程度 → 目で拾える範囲
- 人別フィルタは **Phase 2** で検討

### 入力者

- **Phase 1: 課長のみ**（課員には Phase 2 から）
- 空欄＝「まだ把握できていない箇所」として有益

### 使うタイミング

- **週次（週次ミーティング前後）**: 課全体の進捗を整理
- **随時（作業配分時）**: 誰に頼めるか・誰が空いているかを確認

### データ

- API / DB 不要（JSON モックで完結）
- Pane 4 備考: `string[]`（時系列）

## 9. 採用しなかった案（ぶれ防止用）

| 案 | 採用しなかった理由 |
|----|--------------------|
| Pane1＝課員名 | 目標達成への貢献が見えにくくなる |
| 切り替えビュー（目標別 / 人別） | Phase 1 には過剰。Phase 2 で検討 |
| 未割当専用列 | 行のバッジ方式の方が列を増やさず見やすい |
| 期限必須 | 入力が止まるリスクがある |
| 課員が Phase 1 から入力 | 粒度・書き方がバラバラになりやすい |
| 親子タスク | 担当の把握が曖昧になる |
