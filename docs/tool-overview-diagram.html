開発管理課タスク状況管理（2026）
ツール図解

課長が週次ミーティング前に5分で状況把握できる。
4ペイン構成・Neon DB 永続化・Vercel 公開。

Next.js 16 Neon PostgreSQL Vercel 4ペイン構成 目標ビュー / 課員ビュー 2026-06-28 時点

SECTION 1

ツールの画面

4ペインの横並びレイアウト。左から「カテゴリー選択 → タスク一覧 → 状況・次の一手 → 備考」の順で情報が流れる。

目標ビュー（デフォルト）
Pane 1 に年度目標の一覧。目標をクリックするとその目標に紐づくタスクだけが Pane 2 に表示される。 ヘッダーの数字（未割当・進行中・期日警告・完了）をクリックするとその条件で絞り込みが入る。
課員ビュー
Pane 1 に課員の一覧と担当タスク数。課員をクリックするとその課員のタスクだけが表示される。 「課員一覧」と「目標ビュー」はヘッダー右上のトグルで切り替え。
4ペインの役割分担
PANE 1
カテゴリー
（年度目標 / 課員）
ビューに応じて切り替わる。目標ビューでは年度目標、課員ビューでは課員名＋担当数を表示。
PANE 2
タスク一覧
（ステータス別）
未着手 / 進行中 / 保留 / 完了 の4グループに自動分類。タスクをクリックで Pane 3 へ。
PANE 3
状況・次の一手
担当者・期日・状況・次アクションを編集。フィールドを外れると自動保存（blur 保存）。
PANE 4
備考（時系列メモ）
「次の一手」は Pane 3 だけ。Pane 4 は会議メモ・経緯など時系列の補足専用。

SECTION 3

保存先と、それを選んだ理由

Markdown / JSON / DB の3択を比較した結果、タスクの実データは PostgreSQL（Neon）を選択。

選択肢 A

Markdown ファイル

git 管理できて人間が読みやすい。しかし「複数フィールドの更新」「複数人参照」には向かない。

✗ 選択しなかった — 複数フィールド更新・共有が困難
選択肢 B

JSON ファイル

構造化データを手軽に扱える。マスタ（目標・課員）には使用。しかしタスクを全員が同時に更新するには競合リスクがある。

△ マスタデータのみ使用 — タスク本体は不採用
選択肢 C ✓ 採用

PostgreSQL（Neon）

ブラウザをまたいで即時反映。複数フィールドの部分更新が安全。Vercel との親和性が高く、無料枠で運用可能。

✓ タスクデータの保存先に採用
Neon を選んだ3つの理由
  1. ブラウザをまたいでリアルタイムに共有できる（JSON では1人が上書きすると他人の変更が消える）
  2. フィールドごとに部分更新できる（担当者だけ変える、期日だけ変える、などが競合なく安全）
  3. Vercel サーバーレス関数との相性が良い（Neon HTTP ドライバーで接続プールなしでも動作する）

リージョンはシンガポール（ap-southeast-1）。Vercel のシンガポールエッジと近く、レイテンシを最小化。

SECTION 4

工夫したポイント

「余分な操作を減らす」「見落としを減らす」の2軸で UIを繰り返し改善した。

①

担当者をフリーテキストから Select（選択式）に変更

✗ 以前：自由入力 → 「小杉」「コスギ」「K.Kosugi」と人によって表記がばらつく
✓ 改善：課員マスタから選ぶだけ → 名前の表記ゆれがなくなる
効果：集計・絞り込みの精度が上がる。課員ビューの担当タスク数も正確に集計できる
②

保存ボタン廃止 → フィールドを外れると自動保存（blur 保存）

✗ 以前：入力後に「保存」ボタンを押す必要がある → 押し忘れでデータが消える
✓ 改善：フォーカスが外れた瞬間に PATCH リクエストが飛ぶ → 操作ゼロで保存
効果：「保存し忘れ」が構造的になくなる。入力に集中できる
③

ヘッダーの数字をクリックでタスクを絞り込み

ヘッダーに「未割当 3 / 進行中 9 / 期日警告 7 / 完了 1」が常時表示されている。 この数字をクリックするとその条件だけに絞り込まれ、もう一度クリックで解除。 「未割当 3」を見てから Pane 2 に探しに行く往復がなくなる。

効果：異常値（未割当・期日警告）を発見してから対象タスクに到達するまで1クリック
④

タスク切り替え時に Pane 3 を先頭へスクロール

タスクを切り替えると Pane 3（状況・次の一手）の内容が新しいタスクに切り替わる。 以前は前のタスクでスクロールした位置のまま表示されていたため、担当者・期日欄が見えない状態で表示されていた。 タスク選択と同時に scrollTop を 0 にリセットすることで解決。

効果：切り替えるたびに最重要フィールド（担当者・期日）が常に見える位置から始まる
⑤

ヘッダーを1段に統合・タイトル中央揃え・文字を25px に拡大

✗ 以前：ヘッダー2段、パンくずなど情報量が多く重かった
✓ 改善：1段化してタイトルを画面中央に。ステータス数字だけ残す
効果：ヘッダーの圧迫感がなくなり、作業エリアが広くなった
⑥

「次の一手」は Pane 3 だけ、備考は Pane 4 だけに分離

設計初期は「次の一手もメモ欄に書けばいい」という案もあった。 しかし週次ミーティング前に「今週何をするか」を一瞬で確認するには、 公式のアクションと時系列メモが混在するとノイズになる。 Pane 3 に「次の一手」専用欄、Pane 4 を備考専用に分けることで確認が1クリックで完結する。

効果：「次に何をするか」が常に同じ場所にある。会議前に迷わない

SECTION 5

苦戦したポイント

コードを書く時間より「何を作らないか・どう妥協するか」の判断に時間がかかった。

苦戦① 認証（Basic Auth）が Chrome で動かなかった

課員展開前にパスワード保護をしようと Basic Auth を実装した。 ローカルでは動いたが、Chrome は Basic Auth のポップアップを表示しない仕様があり、 本番環境（Vercel）では認証画面が出ない状態になった。 設定を何度変えても解消できず断念。

→ 未解決：次回は専用ログインページ（パスワードフォーム + Cookie）で実装し直す

苦戦② データ保存方式の選定（JSON か DB か）

最初は JSON ファイルだけでデータを管理していた。 しかし「ブラウザ間でリアルタイムに共有する」「複数フィールドを部分更新する」 の2要件を満たすために Neon PostgreSQL に移行した。 マイグレーションスクリプトとシードデータ投入で1日かかった。

→ 結論：DB 移行は正しい選択。課員展開後の競合問題がなくなった

苦戦③ Vercel へのデプロイが何度も失敗した

GitHub Actions の設定ミス、コミット作者名の不一致、 非公開リポジトリの制限など、デプロイが途中で止まる原因を1つずつ潰した。 リポジトリ公開・作者名統一・GitHub Actions 再設定でようやく安定。

→ 結論：リポジトリ公開＋Vercel Git 連携が最もシンプルで安定した

苦戦④ エクスポート / インポート機能の範囲判断

バックアップ用のエクスポート（JSON ダウンロード）機能を実装したが、 課員展開の前に「使う人が混乱しないか」を優先してヘッダーから非表示に変更した。 Phase 2 での課員自走フェーズで再検討する。

→ 結論：使われない機能は出さない。Phase 2 で必要なら復活させる

苦戦⑤ グリルで Pane の役割を決め切る

「Pane 1 を課員名にするか目標にするか」「Pane 3 と 4 を分けるか」など、 毎回「便利そう」な案が出てきたが、4ペインの左→右の情報の流れが弱まる案は全て棄却した。

→ 結論：目標ビュー / 課員ビュー切り替えで「両方の見方」を実現。Pane の役割はぶれずに固定
